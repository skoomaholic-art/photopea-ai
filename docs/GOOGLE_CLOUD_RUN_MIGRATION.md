# Poster Editor: переезд именно на Google Cloud Run

Код готовится для **Google Cloud Run**, не Firebase. Этот набор изменений не публикует приложение и не создаёт платные ресурсы. Текущие GitHub Pages и Cloudflare Worker продолжают работать, пока новая версия не будет опубликована и подтверждена.

## Почему Cloud Run

Poster Editor имеет рабочий Node HTTP-сервер (`scripts/dev-server.mjs`) со статической раздачей и API. Dockerfile собирает прежний клиентский allowlist и включает Node API в **одном** сервисе Google Cloud Run. Не переносим платные AI-ключи. Бесплатные резервные источники TVmaze/Wikimedia поддерживаются существующим Node API; полноценный TMDB/Fanart зависит от легальных и действующих ключей поставщиков.

Для тарифа Cloud Run с оплатой по запросам Google предоставляет постоянно бесплатный месячный объём запросов, CPU и памяти. **Это не полностью бесплатный продукт без рисков**: Google Cloud требует подключённый платёжный аккаунт даже при использовании Free Tier, перерасход выставляется к оплате. В режиме оплаты по запросам бесплатно до 2 млн запросов, 180 000 vCPU-секунд и 360 000 GiB-секунд в месяц (эквивалент тарифного региона Tier 1). Бесплатный интернет-трафик Cloud Run: только 1 GiB в месяц в пределах Северной Америки; для пользователей Казахстана исходящий трафик тарифицируется по соответствующим правилам, а Cloud Build и Artifact Registry считаются отдельно. **Free Tier сам по себе не гарантирует нулевой счёт**. Не запускать deploy без разрешения владельца на возможные расходы. Правила: https://cloud.google.com/run/pricing и https://docs.cloud.google.com/billing/docs.

### Настройки, которые уменьшают расходы

- `--min-instances=0`: сервис засыпает без запросов.
- `--max-instances=1`: не запускает дополнительные инстансы при нагрузке; **не является денежным лимитом**.
- `--cpu-throttling`, 1 vCPU, 512 MiB: режим оплаты по запросам.
- `AI_REQUESTS_ENABLED=false`: платная генерация OpenAI/xAI отключена. Никаких ключей не вшито в Docker image.
- Workflow `deploy-google-cloud-run.yml` запускается **только вручную**, и лишь когда владелец отдельно выставит GitHub `GCP_DEPLOY_ENABLED=true`. Автоматического развертывания или активации Google API нет.

## Что уже подготовлено в репозитории

`Dockerfile`, `.dockerignore`, ручной workflow `.github/workflows/deploy-google-cloud-run.yml`. Приложение запускается существующим Node сервером на Cloud Run `PORT`, клиент использует API на том же домене. Логика редактора, TOP10, Photopea и Паровозика не меняется.

## Для первого развёртывания в существующем Google Cloud аккаунте

1. Выбрать целевой Google Cloud проект; отдельный проект удобнее для контроля расходов, но этот PR новый проект не создаёт. Не менять проект SLP без намерения.
2. Проверить действующий биллинг и бесплатно ли предполагаемое использование; выбрать бюджет и уведомления. **Обычный бюджет с уведомлениями не останавливает списания.** Preview Spend Caps ограничивает отдельные сервисы (включая Cloud Run) с задержкой, но не гарантирует нулевые расходы и не покрывает все сопутствующие услуги: https://docs.cloud.google.com/billing/docs/how-to/budgets-spend-caps.
3. С согласия владельца включить необходимые API Cloud Run, Cloud Build и Artifact Registry. Разрешения для source deploy: https://docs.cloud.google.com/run/docs/deploying-source-code.
4. Настроить безопасную GitHub -> Google Cloud аутентификацию через Workload Identity Federation (без сохранения статических JSON-ключей в репозитории): https://docs.cloud.google.com/iam/docs/workload-identity-federation-with-deployment-pipelines.
5. В настройках GitHub Actions **Variables** указать `GCP_PROJECT_ID`, `GCP_WIF_PROVIDER` (полное имя провайдера), `GCP_DEPLOY_SA` (email сервисного аккаунта), по желанию `GCP_REGION` (по умолчанию `me-central1`), а **после подтверждения условий** выставить `GCP_DEPLOY_ENABLED=true`.
6. После merge PR в main вручную вызвать workflow `Deploy Poster Editor to Google Cloud Run (manual)`. До явного запуска ничего в Google Cloud не меняется.

## Что критично не потерять

- Существующий GitHub Pages остаётся доступным; **не удалять** его до подтверждённой миграции.
- IndexedDB, локальный архив логотипов, автосохранение и PSD привязаны к домену старого сайта: данные автоматически не переедут. Для полного переноса нужна отдельная функция экспорта/импорта архива. Сохранение одного проекта в JSON **не переносит весь архив**.
- В предыдущей веб-версии поиск/AI были связаны с Cloudflare Worker. На новом домене Node-сервер предоставит свои API-роуты; для равнозначного TMDB/Fanart потребуется перенастроить существующие ключи на Google Cloud безопасно и с учётом лицензий. До этого **не выключать** старый Worker. Платные API не включать.
